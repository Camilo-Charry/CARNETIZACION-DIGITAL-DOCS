\section{Metodología de investigación aplicada}

El desarrollo del Sistema de Carnetización Digital y Gestión de Eventos siguió un enfoque de investigación aplicada, combinando revisión sistemática de literatura con desarrollo iterativo de software. Se aplicaron metodologías ágiles para asegurar flexibilidad y entrega incremental, priorizando la simplicidad y viabilidad técnica dadas las limitaciones de tiempo.

\subsection{Diseño del Sistema}

Basado en la revisión de literatura, se diseñó un sistema híbrido centrado en códigos QR estáticos para identificación y gestión de eventos. La arquitectura se divide en dos componentes principales: una plataforma web para administradores y una aplicación móvil para usuarios finales.

\subsubsection{Códigos QR como Tecnología Principal}

Se adoptaron códigos QR estáticos generados por el sistema, asignados a cada usuario registrado. Estos contienen información básica de identificación y permiten el acceso a eventos activos.

Justificación: La literatura (e.g., Hamzah et al., 2021; Hendrawan et al., 2025) confirma que los QR ofrecen bajo costo, universalidad y facilidad de implementación. No requieren hardware adicional más allá de una cámara móvil, y su efectividad en entornos educativos está probada, con mejoras en precisión y reducción de errores administrativos.

El flujo operativo es simple: el administrador crea un evento y genera un QR único para él. Los usuarios escanean el QR para confirmar asistencia si el evento está activo, consultando una base de datos central para validación.

\subsubsection{RFID como Extensión Futura (No Implementada)}

Aunque la literatura (Mares et al., 2018) destaca beneficios del RFID para registros de alta velocidad (reducción del 50% en tiempos), su implementación se pospuso por limitaciones temporales y complejidad de hardware. La arquitectura está diseñada para ser extensible, permitiendo integración futura sin cambios mayores.

\subsection{Valor Agregado: Automatización y Simplicidad}

El sistema se enfoca en automatizar tareas administrativas post-registro, inspirado en hallazgos de la literatura (e.g., Al Amin et al., 2024; Siew et al., 2023):

- **Gestión de Eventos**: Creación y configuración de eventos, control de acceso basado en roles (estudiantes, docentes, empleados).
- **Registro de Asistencia**: Escaneo QR para marcar presencia, con validación en tiempo real.
- **Generación de Reportes**: Reportes automáticos en formatos CSV/XLS, eliminando transcripción manual.
- **Cálculos Automáticos**: Porcentajes de asistencia y estadísticas básicas.

Esta simplicidad asegura aceptación por usuarios, como se observa en evaluaciones de sistemas similares (Perin, 2025).

\subsection{Proceso de Desarrollo}

Se aplicó una metodología ágil híbrida, combinando elementos de Scrum y desarrollo iterativo, dada la escala del proyecto. Fases principales:

1. **Análisis y Diseño**: Revisión de literatura, definición de requisitos funcionales (e.g., gestión de usuarios, eventos, reportes).
2. **Implementación Iterativa**: Desarrollo incremental, con prototipos para validación temprana.
3. **Pruebas y Validación**: Pruebas unitarias, integración y aceptación, enfocadas en funcionalidad QR y usabilidad.
4. **Despliegue**: Configuración de entornos web y móvil, con monitoreo básico.

Herramientas: Lenguajes como JavaScript/Node.js para backend, React para frontend web, React Native para móvil; base de datos relacional (e.g., PostgreSQL); integración con bibliotecas QR (e.g., qrcode.js).

\subsection{Datos e Instrumentos}

Se recolectaron métricas de desarrollo: tiempo de implementación, defectos encontrados, cobertura de pruebas. Datos cualitativos incluyen feedback de usuarios en pruebas piloto. La validez se aseguró mediante triangulación de fuentes (literatura, pruebas, observaciones).

El enfoque priorizó viabilidad sobre complejidad, alineándose con recomendaciones de la literatura para proyectos con recursos limitados (e.g., Razzaq y Ghayyur, 2023).
